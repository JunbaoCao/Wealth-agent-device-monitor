# 🧠 监察师 · 知识图谱与 RAG 接入框架

> 把设备档案、资料库变成可检索的 RAG 知识图谱。**通用版**，任何电脑都能用本框架接入。
> 相关：`README.md` · `format/格式与编码.md` · `docs/通用技能.md`

---

## 一、RAG 是什么（4个零件）

1. **嵌入模型（Embedding）** — 文字转向量，用于"找相似"
2. **知识库（Knowledge Base）** — 存原始资料 + 向量索引
3. **重排序（Rerank）** — 检索后把最相关的排前面
4. **LLM（大模型）** — 把检索结果组织成最终回答

## 二、三层体系

```
[第1层] 原始数据层 ── 设备档案.md、日志、上传的文件
        ↓
[第2层] 流程备份层 ── 每次处理流程留档成 md（可回溯、可复现）
        ↓
[第3层] 知识图谱层 ── 把档案和备份向量化，变成可检索的 RAG 知识库
```

## 三、落地步骤（通用）

### 1. 建立目录骨架
```
监察师/
├── 设备档案.md
├── 日志/              ← 心跳+操作
├── 流程备份/          ← 每次处理留档
├── 上传文件/          ← 用户上传的原件
└── 知识库/            ← RAG向量化结果
```

### 2. 流程备份规范
每次处理（转换/诊断/更新）都记录成 md：
```
# 流程备份：<动作名称>
- 时间：YYYY-MM-DD HH:MM:SS
- 动作：<做了什么>
- 输入：<文件路径/数据>
- 输出：<结果路径/结论>
- 验证：<怎么验证它对了>
- 备注：<异常/注意点>
```

### 3. 向量化知识库（用已有工具，零新装）
| 步骤 | 用什么 |
|------|--------|
| 汇总 | `fs` 读取全部 md |
| 分块 | Python 按标题/段落切块 |
| 向量化 | 本地 qwen3-embedding 或 云端 embedding API |
| 存储 | `storage`/`storageDomain` 或文件 |
| 检索 | 先向量检索，再让 AI 基于结果回答 |

### 4. 嵌入/重排序来源（跨平台通用）
- **本地嵌入**：qwen3-embedding 等本地 ONNX 模型（离线免费）
- **云端嵌入+重排序**：SiliconFlow / 其他API（质量更高，需Key）
- **OCR**：pp-ocrv6 等本地模型，PDF/图片转文字

## 四、格式转换层（md / json / js / python 互转）

| 从 → 到 | 用什么 |
|---------|--------|
| md → js/ts | Node.js |
| md → python | Python |
| md → json | Node/Python |
| json/js → md | Node/Python |
| PDF/Office → 文本 | OCR / Python |

每次转换都写流程备份 md，记录输入输出，保证可复现可验证——这就是"机器了解清楚"。
